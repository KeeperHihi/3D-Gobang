# Nebula Cube 3D 五子棋

在线匹配的 3D 联机五子棋。棋盘是立方体，任意空间方向连成 5 子即获胜。

## 当前默认规则

- 棋盘尺寸：`8 x 8 x 8`
- 连线胜利条件：`5 子`
- 每回合默认落子时限：`300s`

## 主要交互（已落地）

- 旋转/缩放镜头后，视角保持当前位置，不会被系统自动复位。
- “战术辅助提示”默认关闭；仅在玩家主动开启后显示候选提示位。
- 对手刚落子的格子会闪烁数次，提醒当前玩家。
- 点击非聚焦层格子不会触发切层或落子，避免误触导致视角层级跳变。
- 聚焦层仅支持通过 HUD “上一层/下一层”按钮或自定义快捷键切换。
- 交互提示已统一为单活动提示流：同一时段只显示一个当前最高优先级提示，高优先提示结束后旧低优先提示不会回弹。
- 鼠标移入候选落子位立即高亮。
- 外层立方体线框已移除。
- 支持通过滑杆连续调节“未聚焦层”显示清晰度（透明度）。
- HUD 提供“设置”弹层入口，支持右上角 `×` 或点击游戏场景关闭。
- 默认 HUD 常驻显示当前回合倒计时，无需展开额外状态。
- 设置弹层支持自定义“上层/下层”快捷键（默认 `a/d`，本地持久化）。
- 当轮到你且“战术辅助提示”关闭时，主动作按钮会提供“一键开启提示并推荐”，避免操作死路。
- 当暂不可落子（如等待对手/网络重连/提交中）时，主动作文案会明确提示可切层观察，减少被动等待感。
- HUD 连接提示已与主动作文案统一：连接异常且棋盘可观察时会提示“可切层观察”，棋盘未就绪时仅提示等待恢复。
- 连接态语义已单源化：HUD 网络状态、主动作按钮标签、Spotlight 告警强度统一按 `connecting/reconnecting/offline` 阶梯展示，首连降噪、异常保真。
- 若开启“超时护航”，即使提示开关关闭，在临近超时窗口也会自动执行一次兜底合法落子（优先制胜/防守）。
- 匹配大厅支持在线玩家列表、昵称编辑与点名挑战（发起/应战/拒绝/取消/超时），并与快速匹配并行可用。
- 匹配页会在在线空闲与“开始匹配”意图阶段提前预热 3D 战场，降低进房等待感。
- 匹配页主动作已做连接语义桥接：`connecting/reconnecting/offline` 下按钮文案与禁用原因会同步解释当前状态，避免“按钮不可点但文案像可点”。
- 匹配页次级动作（取消匹配/重试预热）也已语义桥接：禁用时会给出明确原因，主次动作解释保持一致。
- 匹配页阻断解释已收敛为单通道主提示：同源禁用原因会自动去重，避免“同一状态重复提醒”带来的阅读负担。
- 预热提示已做上下文门控：当连接/恢复阻断导致“暂不可重试”时，提示会自动切换为“恢复后可重试”语气，避免语义冲突。
- 预热失败时可在匹配页使用“**一键重试预热**”恢复，不影响继续匹配主流程。
- 预热策略具备网络感知：弱网或省流量模式下默认按“用户意图触发”预热，避免空闲时盲目下载大资源。
- 排队中若预热失败会自动按退避节奏重试（最多 3 次），并保留手动重试入口。
- 对局冷启动采用分阶段渲染：先保证棋盘可交互与稳帧，再渐进恢复星空/粒子等氛围特效。
- 棋盘主层已切换为分桶实例化渲染（instanced mesh），降低稳态 draw call 与交互抖动。
- 悬停高亮已与主实例布局解耦：采用独立 overlay 实时反馈，避免高频 hover 触发整盘重算。
- HUD 时钟已升级为自适应刷新频率（关键窗口提频、平稳阶段降频），减少长局空转重渲染。
- `BoardScene` 已进行 memo 渲染隔离，HUD 时钟刷新不再默认拉动 3D 场景重渲染。
- 对局场景已采用“核心可玩优先 + 特效后流式加载”：棋盘交互先就绪，星空/粒子/胜线特效按阶段补齐。
- 胜线主渲染已回归核心链路：任意特效档位下终局胜线可即时可见，VFX 仅做增强表现。
- VFX 档位已加入“迟滞阈值 + 最小维持窗口 + 紧急降档”稳定策略，降低阈值附近闪变并优先保障操作流畅。
- 自动模式已加入“设备能力自校准 + 跨局记忆”：仅在前台可见且窗口聚焦时学习样本，首局采样后会在本地缓存建议初始画质/VFX，过期或设备变化时自动回退默认策略。
- 对局进入采用“Room Shell First”：房间 HUD/状态先渲染，棋盘按局部异步加载并支持失败重试，减少整页等待感。
- 棋盘加载失败后会优先自动退避重试（1s/2s/4s）；达到上限后再提示手动重试，减少用户反复操作。
- 若命中不可恢复的分包错误（如资源版本切换导致 chunk 失效），会直接提供“立即刷新并恢复战局”一键自愈入口。
- 渲染自动调档已具备前后台感知：后台冻结自动质量/VFX调整，回到前台后先经历短暂复稳窗口再恢复自适应，减少视觉突变。
- 匹配阶段预热升级为“双阶段”：先预热房间壳，再按网络策略预热棋盘分包；命中时可进一步缩短“匹配成功到可落子”的等待。
- 自动质量模式下，低 FPS 会触发“冷静模式”降低渲染预算以优先保证流畅度。

## 本地启动

### 环境要求

- Node.js 18+
- npm 9+

### 安装依赖

```bash
npm install
npm --prefix server install
```

### 开发模式

```bash
npm run dev
```

- 前端（Vite）：`http://localhost:5173`
- 后端（Socket.IO + Express）：`http://localhost:3001`

## 测试与构建

```bash
npm test
npm run build
```

## 可选环境变量

前端：

- `VITE_SERVER_URL`：后端地址，默认 `http://localhost:3001`

后端：

- `PORT`：服务端口，默认 `3001`
- `FRONTEND_ORIGIN`：允许跨域来源，默认 `http://localhost:5173`

## 目录结构

- `src/`：前端页面、UI、交互逻辑、3D 场景
- `server/src/`：匹配、房间状态、Socket 事件
- `shared/`：前后端共享协议与棋盘/胜负判定逻辑
